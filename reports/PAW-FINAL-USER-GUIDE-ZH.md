# PAW 迁移工具 中文使用指南（v2.8.1 预硬件版）

这份指南写给第一次使用的你。它只讲“怎么用、会看到什么、什么不能做”。
本版所有测试都在虚拟机里完成，**还没有在真实 ASUS 主机、真实 U 盘和真实 SSD 上跑过**。

## 1. 它是做什么的

PAW 把一台旧 Ubuntu 电脑的系统、软件和数据，搬到一块更大的新硬盘上；
搬完后新硬盘可以自己启动，旧硬盘保持原样，方便回退。

它不会替你决定“哪块盘能删”。源盘、目标盘、U 盘都要你现场确认。

## 2. 开始前准备

1. 一台能用的 Windows 电脑，用来制作启动 U 盘。
2. 一个 **至少 32GB** 的 U 盘（会被写入 PAW 系统，里面原有数据请先备份）。
3. 旧电脑的 Ubuntu 系统盘（源盘），以及一块 **不小于源盘已用空间** 的新 SSD（目标盘）。
4. 目标盘里的数据必须先备份；PAW 会清空目标盘的分区签名。
5. 记住 U 盘序列号的后 6 位；PAWDATA 初始化时会让你输入它，防止选错盘。

## 3. 制作启动 U 盘

1. 在 Windows 上用写盘工具把 `paw-live-*.iso` 写入 U 盘（不是复制文件）。
2. 写完后 U 盘会出现一个小的启动分区，这是正常的。
3. 安全弹出 U 盘。

> 不要用“只读挂载”方式测试 PAWDATA。真实 U 盘必须可写；如果写保护开关打开，
> 程序会在写分区前直接停止，不会留下半个分区。

## 4. 从 U 盘启动旧电脑

1. 开机按主板启动菜单键（ASUS 常见是 `F8`），选 U 盘。
2. 看到 `PAW` 中文控制台后，按屏幕提示操作。
3. 先让程序识别源盘和目标盘；屏幕会显示容量、序列号、接口。
4. **逐项核对**：源盘是旧系统盘，目标盘是新 SSD，U 盘是启动盘。错一项就退出重来。

## 5. PAWDATA 是什么

PAWDATA 是追加在启动 U 盘尾部的一个小分区，用来保存迁移记录和“持久化令牌”。
它只格式化**新追加的分区**，不会动 U 盘原来的 ISO 启动分区。

第一次启动会要求输入 U 盘序列号后 6 位，然后自动创建 PAWDATA。
第二次用同一张 U 盘启动时，程序会认出它，不再询问，并报告
`PAWDATA already initialized`。这说明持久化正常。

## 6. 迁移过程会看到什么

| 屏幕/日志 | 含义 | 你要做什么 |
|---|---|---|
| `source_os PASS` | 已只读挂载旧系统 | 核对发行版和内核 |
| `pawdata PASS` | U 盘记录分区正常 | 无需操作 |
| `target_enrollment PASS` | 已确认目标 SSD | 核对容量/序列号 |
| `clone_complete` | 数据已写入目标盘 | 不要断电 |
| `sha256_verify PASS` | 独立回读校验通过 | 等待修复/扩容 |
| `preboot_handoff PASS` | 重启前交接检查通过 | 可以重启 |
| `PAW3_CHAIN_RESULT=PASS` | 整条迁移链完成 | 拔掉 U 盘，从新 SSD 启动 |
| `FAIL` / `BLOCKED` | 某一步被门禁拦住 | 拍照记录屏幕，不要强行继续 |

迁移时间取决于数据量。50GiB 源盘在虚拟机里也需要较长时间；真实机器可能更久。
**中途不要拔 U 盘、不要断电、不要按复位键。**

## 7. 迁移完成后

1. 关机，拔掉 U 盘。
2. 开机进入 BIOS，把新 SSD 设为第一启动项。
3. 第一次启动会做首次启动检查；通过后才算真正完成。
4. 旧盘先保留至少一周，确认新系统、网络、业务都正常后再处理。

## 8. 绝对不要做

- 不要把 PAW 的“虚拟测试 PASS”当成你的真实机器已经 PASS。
- 不要在未备份的目标盘上运行。
- 不要同时接两块容量和型号都一样的目标盘。
- 不要在生产 VPS 上直接试；本版没有登录或修改任何生产服务器。
- 不要删除 U 盘上的 PAWDATA 来“重置”；这会让下一次启动重新询问序列号。

## 9. 本版已验证 / 未验证

| 项目 | 状态 |
|---|---|
| QEMU 虚拟 USB 启动、PAWDATA 两轮持久化 | 已验证 PASS |
| 中文控制台字体与五个界面场景 | 已验证（CI） |
| 12GiB 虚拟全链路、SHA256、目标盘启动 | 已验证 PASS |
| 50GiB 全链路 | 只验证到 source/PAWDATA，**未完整跑完** |
| 真实 ASUS BIOS、真实 U 盘、真实 SSD | **未验证** |
| 真实 Tailscale/VLESS/Exit Node/MCP | **未验证** |

## 10. 出问题怎么办

1. 先拍照：屏幕上的步骤名、`PASS/FAIL`、错误码。
2. 不要反复重试写盘；同一错误最多试 2 次。
3. 把照片和 `PAW3_STEP` 日志行一起发给维护者。
4. 如果程序在写分区前停止，U 盘原有启动分区不会被改；可以重新制作 U 盘再试。

一句话：**先备份、再核对、看到 PASS 才继续；不确定就停。**
