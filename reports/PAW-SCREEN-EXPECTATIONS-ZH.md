# PAW v2.7 现场对照：你应该看到什么

这几张图不是画的，是 **CI 里 QEMU 真实渲染后截屏**、再由同一套测试用字形逐格解码、
并与随 ISO 附带的 PSF 字库逐字比对过的画面（Run `42857316370`，5 例 / 96 断言全过）。

怎么用：现场屏幕上出现对应界面时，**对照这里的文字**（型号、容量、序列号、警告语）。
对不上就停下，不要继续按。

> 图里的数据是**模拟值**（`/dev/loop0`、`QEMU-123456`、`QEMU virtual source`），
> 真机上会是你的 TF 卡、你的 SSD、你的旧 VPS。**要对照的是措辞和结构，不是这些数值。**

## 1. 控制台菜单

（截图见交付包 `screens/console-menu.png`；仓库按公开安全策略不存二进制。）

必须包含（原文）：

```
==============================================
 PAW 迁移准备控制台（v2.7）
==============================================
[PAW-MENU-KEYS] 1 Memtest 2 PAWDATA 3 RescueSSH 4 TargetSSD 5 HWCheck 6 Migrate 7 Reports 8 Network 0 Redraw
当前：状态=...
1) 登记 Memtest86+ 人工确认结果
2) 初始化/修复 PAWDATA 持久分区
3) 配置 Rescue SSH 并识别旧 VPS 源盘
4) 登记目标 SSD（只读盘点）
5) 运行目标 SSD 硬件检查（SMART/只读扫描/温度/内存）
6) 最终中文授权并开始迁移
```

**不通过的样子**：只看到 `PAW-MENU-KEYS` 一行 ASCII，中文全是方块或问号 → 字库没生效，
停止并记录。

## 2. PAWDATA 初始化面板

（截图见交付包 `screens/pawdata-panel.png`；仓库按公开安全策略不存二进制。）

必须包含：

```
PAW 首次启动 · PAWDATA 持久分区初始化
只针对当前启动本系统的可移动设备；不会碰其他磁盘。
物理设备：/dev/sdX
型号：...
容量：... bytes（约 ... GiB）
序列号：...
```

核对三件事：**物理设备就是你的 TF 卡**、型号/容量对得上、序列号与卡一致。
任何一项不对，**不要输入确认**。

## 3. 拒绝/不匹配的样子（这是正确行为）

（截图见交付包 `screens/pawdata-reject.png`；仓库按公开安全策略不存二进制。）

输入错的序列号后缀时，界面会明确拒绝并说明没有改动任何东西。
**看到这种画面是好事**，说明保护在起作用；不要以为出错就乱试。

## 4. 最终迁移授权面板（最重要的一屏）

（截图见交付包 `screens/final-authorization.png`；仓库按公开安全策略不存二进制。）

必须逐行包含（原文）：

```
PAW 最终迁移授权（请完整阅读后再确认）
硬件检查：PASS（内存验证方式：OPERATOR_CONFIRMED）
源系统：Rescue Mode，型号=...，容量=... bytes，根分区=...
源盘序列号：... 或 不可用（使用组合身份）
源盘组合身份：...
固定 SSH 主机指纹：SHA256:...
目标 SSD：设备=...，型号=...，容量=... bytes
目标序列号：...
数据来源：固定 SSH 主机指纹的 Rescue Mode 整盘流（远端 zstd，SSH 加密传输，本地解压写入）
网络：本次启动已验证 Rescue SSH；不依赖旧 Ubuntu 内部的 VLESS/Tailscale 服务。
数据损失：目标 SSD 的整盘内容将被源盘覆盖，目标盘原有分区和数据会全部丢失。
恢复：离线修复前会在 PAWDATA 保留配置备份；但不等于可恢复目标盘原有数据。
```

然后才会出现：

```
如确认覆盖，请输入目标 SSD 序列号最后 6 位：
```

**必须逐项核对**：源系统容量 ≥ 目标盘容量？目标序列号是你要覆盖的那块盘？
`DATA LOSS` 那行读完了？任何一项犹豫就按 `Ctrl-C` 退出，什么都不写。

## 5. 输错 6 位时的样子

（截图见交付包 `screens/final-reject.png`；仓库按公开安全策略不存二进制。）

会显示确认值与目标序列号不匹配、已安全停止、**没有写入任何数据**。
这是设计好的保护，重新按 `6` 再来即可。
