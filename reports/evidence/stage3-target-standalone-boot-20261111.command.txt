PAW Stage 3 — standalone target-disk boot verification (2026-11-11)

Purpose
  Prove that the cloned target disk boots to a real Ubuntu getty login prompt on
  its own, with SeaBIOS as the firmware and NO direct kernel/initrd. This is the
  independent verification of the chain's final target_boot step; the chain
  process itself was killed by the outer scheduler after it had emitted
  chain_pass=True, so it reported target_boot=False / qemu_rc=-9.

QEMU invocation (portable QEMU 8.2.2, TCG because /dev/kvm is absent)
  qemu-system-x86_64 \
    -accel tcg,thread=multi -cpu max -smp 2 -m 3072 \
    -L <portable-qemu-data-dir> -no-user-config -nodefaults \
    -display none -vga std -monitor none -rtc base=utc \
    -boot order=c,menu=off \
    -chardev socket,id=ser0,path=<work>/serial.sock,server=on,wait=off,logfile=<work>/serial.log,logappend=off \
    -serial chardev:ser0 \
    -qmp unix:<work>/qmp.sock,server=on,wait=off \
    -drive file=<lab>/boot/target.img,if=none,id=vda,format=raw,cache=unsafe \
    -device virtio-blk-pci,drive=vda,bootindex=1,serial=PAW-DST-123456 \
    -netdev user,id=n0 -device virtio-net-pci,netdev=n0

  There is no -kernel and no -initrd argument. target.img is the only disk.

Result
  status=TARGET_BOOT_SEEN, qemu_rc=0, serial log 56,275 bytes.
  Kernel 6.8.0-147-generic (the cloned Ubuntu kernel, not the live ISO kernel).
  Serial console: "Ubuntu 24.04.5 LTS ubuntu ttyS0" followed by "ubuntu login:".
  QMP screendump captured the login screen; PNG copy is in this directory.
