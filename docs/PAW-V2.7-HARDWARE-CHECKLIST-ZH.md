# PAW v2.7 实机验证清单（照着做就行）

这份清单只写**你在实体机器上必须亲自做的事**，以及每一步屏幕上应该出现什么。
云端的构建与虚拟测试已经全部通过（Run `42804949796` 与之后的守卫验证），但那
不等于实机通过；下面 7 项做完之前，交付状态仍是"实机未验证"。

适用 ISO：`paw-live-amd64.iso`，930,086,912 bytes，
SHA256 `43488236…a34fe39939f`（以同一 Run 的侧车文件为准）。

---

## 先记住三条

1. **任何一步出现 FAIL / WARN，就停下**，不要"再试一次"跳过身份或内存门槛。
2. 最终授权一旦确认，**目标 SSD 整盘会被覆盖**；目标盘原有分区和数据全部丢失。
3. 旧 VPS 在迁移成功并通过新机验证之前，**保持生产运行**，不要停、不要改。

---

## 第 1 项：TF 卡写入与回读

**做什么**

1. 在 Windows 上核对 ISO 哈希：`Get-FileHash -Algorithm SHA256 paw-live-amd64.iso`。
2. 用 Rufus 选择该 ISO，**DD 模式**写入 TF 卡（图形步骤见
   `reports/TF-CARD-RUFUS-GUIDE.md`）。

**预期**

- 哈希与 `43488236…a34fe39939f` 完全一致（不一致就重新下载，不要写卡）。
- Rufus 显示"准备就绪"，写入过程无错误。

**如果不对**

- 哈希不一致：说明下载损坏或被替换，重新下载同一 Run 的 Artifact。
- Rufus 报写入失败：先怀疑读卡器/卡本身，换卡再试；不要用"快速格式化"绕过。

---

## 第 2 项：真实主板启动（Legacy / CSM）

**做什么**

1. 目标电脑进 BIOS，设为 **Legacy / CSM 启动**（不是纯 UEFI）。
2. 从 TF 卡启动，等待控制台出现。

**预期屏幕**（真实字符串）

```
==============================================
 PAW 迁移准备控制台（v2.7）
==============================================
[PAW-MENU-KEYS] 1 Memtest 2 PAWDATA 3 RescueSSH 4 TargetSSD 5 HWCheck 6 Migrate 7 Reports 8 Network 0 Redraw
1) 登记 Memtest86+ 人工确认结果
...
```

**如果不对**

- 黑屏/进不去：确认 CSM 已开、TF 卡是第一启动项；屏幕若显示乱码方块，
  说明字体没加载，记录现象后停下（这属于真实字形问题，云端无法替代）。
- 只看到"输入最后 6 位"而看不到面板：这正是本项目修掉的缺陷，若复现请立即
  记录并停止，说明交付 ISO 不是最新版本。

## 第 3 项：物理 Memtest86+（对应菜单 1）

**做什么**

1. 在启动菜单里选 **Memtest86+** 独立启动项（不是 PAW 控制台）。
2. 让它跑**至少 1 轮**，记住错误数。
3. 重启回 PAW 控制台，按 `1` 登记。

**预期屏幕**

```
PAW 内存检测人工确认
本界面只登记操作员在 Memtest86+ 独立启动项中亲眼看到的结果。
它不是机器自动验证，也不是密码学证明；请不要凭猜测填写。
目标 SSD：...
目标序列号：...
本次 PAW Live 启动 ID：...
请选择：
  1) Memtest86+ 已完成至少 1 轮，错误数为 0
  2) Memtest86+ 已完成，但出现错误
  3) 尚未完成、无法确认或不确定
输入 1、2 或 3：
```

**注意**

- 只有选 `1` 才会得到 `OPERATOR_CONFIRMED`；这是**你的目视确认**，不是机器证明。
- 选 `2` 或 `3` 会让后续最终授权拒绝继续，这是设计如此，不要绕过。

**如果不对**

- 面板不出现、或"本次启动 ID"为空：停下并记录（说明启动 ID 绑定有问题）。

## 第 4 项：PAWDATA 初始化（对应菜单 2）

**做什么**

1. 回到菜单按 `2`。
2. 核对面板显示的型号、容量、序列号是否就是这张 TF 卡。
3. 按提示输入**序列号最后 6 位**确认。

**预期屏幕**

```
PAW 首次启动 · PAWDATA 持久分区初始化
只针对当前启动本系统的可移动设备；不会碰其他磁盘。
物理设备：/dev/sdX
型号：...
容量：... bytes（约 ... GiB）
序列号：...
将只追加一个新的 PAWDATA 分区并格式化该新分区；ISO 启动分区不会被格式化。
```

成功后：`PAWDATA 初始化完成；可以继续后续迁移步骤。`

**如果不对**

- 显示的设备不是你的 TF 卡：**不要确认**，直接断电换机排查。
- 它要求格式化已有分区而不是"追加新分区"：停下并记录（说明活动介质识别错了）。

## 第 5 项：真实 SSD 只读盘点与硬件检查（对应菜单 4、5）

**做什么**

1. 按 `4` 登记目标 SSD：先看候选列表，输入编号，再输入该盘序列号最后 6 位。
2. 按 `5` 跑硬件检查（SMART / 只读扫描 / 温度 / 内存）。

**预期屏幕**

```
PAW 目标 SSD 只读盘点（只登记，不写磁盘）
以下为本机可用的非移动、未挂载本地磁盘：
...
输入目标 SSD 对应的编号（只登记，不写磁盘）：
```

选择后：`已选择：设备=... 型号=... 容量=... bytes` / `该目标序列号：...`

**如果不对**

- 候选列表里没有你的 SSD：确认它没被挂载、不是移动盘；不要手输设备名绕过。
- SMART 检查报 FAIL：这块盘不适合承载迁移，换盘。
- 温度异常高或只读扫描有错误：停止，不要继续授权。

## 第 6 项：真实腾讯云 Rescue SSH 与源盘识别（对应菜单 3）

这一步最难，因为它跨两台机器。**建议先只看这一节，把 VNC 和 PAW 两边的窗口摆好再动手。**

### 6.1 先把"三样东西"准备好

| 需要什么 | 从哪来 |
|---|---|
| 旧 VPS 的公网 IP | 腾讯云控制台实例列表，或 Rescue VNC 里执行 `ip -4 addr` |
| SSH 端口 | 一般是 `22`；如果你改过就用改过的 |
| Rescue 环境的 SSH 主机指纹 | **在 Rescue VNC 里执行一条命令得到**（见 6.3） |

另外：PAW 会打印一把**一次性公钥**，你要把它贴到 Rescue 环境的
`/root/.ssh/authorized_keys`（见 6.4）。

### 6.2 进入 Rescue Mode（会停机，时机你定）

1. 腾讯云 CVM 控制台 → 找到旧 VPS 实例 → 在"更多操作 / 运维"里选择**救援模式（Rescue Mode）**。
   不同版本控制台菜单文字略有差异；找不到就在腾讯云文档里搜"救援模式"。
2. 进入后用 **VNC 登录**（控制台自带的"登录"按钮），拿到 root shell。
   救援环境通常不给你原系统的密码，而是自动登录或给临时密码。

> 停机期间旧站不可用。如果你还没准备好，**先退出救援模式**（重启回正常模式），别让它挂着。

### 6.3 在 VNC 里取指纹、开 SSH

在 Rescue VNC 的 root shell 里依次执行：

```sh
# 1) 记录公网 IP（填到 PAW 用）
ip -4 addr show scope global

# 2) 打印 SSH 主机指纹（要抄给 PAW 核对）
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

# 3) 起 sshd（救援镜像有时没有 systemd，用第二条）
systemctl start ssh 2>/dev/null || /usr/sbin/sshd -D &
ss -ltnp | grep ':22'
```

`ssh-keygen -lf` 输出的第二列就是 `SHA256:...`，**PAW 要你粘贴的就是这一串**。

### 6.4 把 PAW 的一次性公钥贴进去

1. 回 PAW 控制台按 `3`，屏幕会先问：

   ```
   输入 Tencent Rescue VNC 中显示的公网主机名或 IPv4（不会写入日志）：
   输入 Rescue SSH 端口 [22]：
   ```

2. 接着显示一把**一次性公钥**（`ssh-ed25519 AAAA... paw-rescue`）。在 VNC 里执行：

   ```sh
   mkdir -p /root/.ssh && chmod 700 /root/.ssh
   echo '把 PAW 屏幕上的整行公钥粘贴到这里' >> /root/.ssh/authorized_keys
   chmod 600 /root/.ssh/authorized_keys
   ```

3. 确认 Tencent **安全组放行 22**：来源只填你当前的公网 IP，不要对任意来源开放。

### 6.5 核对指纹并登记源盘

PAW 屏幕会显示：

```
在 Tencent VNC 中核对 SSH 主机指纹；不要只相信 ssh-keyscan 返回值。
候选 SHA256 指纹：SHA256:...
请把 VNC 显示的完整 SHA256 指纹粘贴到这里：
```

把 6.3 里 `ssh-keygen -lf` 那一串**逐字粘贴**。一致才会继续：

```
主机指纹已核对通过；Rescue SSH 端点已固定。
```

然后再输旧系统**根分区 UUID**（输入不回显）：

```
请输入旧 VPS 根分区 UUID（输入不回显）：
```

> 这个 UUID 从哪里来？在你**原来的旧系统里**（不是救援环境）执行
> `blkid -s UUID -o value /dev/vda1`（根分区设备名按你实际情况，可能是 `vda2`）。
> 如果你平时没记过，可以在进救援前先查好写在纸上；救援环境里原系统的
> `/etc/fstab` 也能读到（`grep ' / ' /etc/fstab`）。

### 6.6 预期的两种结果

- **有 Virtio 序列号**：直接登记序列号。
- **没有序列号**（很常见）：屏幕会写"序列号不可用（使用组合身份）"，然后用
  `主机指纹 + 根 UUID + 父盘 + 容量 + GPT 布局` 的 SHA256 作为身份。
  **这是设计好的回退，不是失败**，不要重试到拿假序列号。

### 6.7 出问题怎么查

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| PAW 一直停在"候选 SHA256 指纹" | 22 没监听，或安全组没放行 | VNC 里 `ss -ltnp | grep :22`；控制台查安全组 |
| 指纹和你抄的不一致 | 连到了别的机器，或主机密钥变了 | **立即停止**，核对 IP；不要强行粘贴 |
| 粘贴后提示"主机指纹不匹配；拒绝连接" | 抄错/多空格/少了 `SHA256:` | 重新抄完整一行；注意大小写和冒号 |
| 提示 `Authenticated Rescue Mode lsblk query failed` | 公钥没贴好，或 `sshd` 不允许 root 公钥登录 | VNC 里检查 `authorized_keys` 权限与内容 |
| 提示 `expected exactly one root UUID match` | UUID 打错，或旧盘有多个同 UUID 分区 | 回到旧系统重新确认根分区 UUID |
| 想放弃 | —— | 控制台退出救援模式并重启回正常模式，PAW 侧什么都不用改 |

## 第 7 项：真实整盘克隆与首次启动（对应菜单 6）

**做什么**

1. 按 `6`，把最终授权面板**逐行读完**（源系统、源盘、目标盘、容量、序列号、
   硬件、网络、数据来源、数据损失、恢复说明）。
2. 输入目标 SSD 序列号最后 6 位。
3. 等待克隆 + SHA256 校验 + GPT/ext4 扩容 + 首次启动准备 + 自动重启。
4. 重启后进新系统，确认能正常启动、网络可用、Tailscale/Xray 状态符合预期。

**预期屏幕（关键行）**

```
PAW 最终迁移授权（请完整阅读后再确认）
硬件检查：PASS（内存验证方式：OPERATOR_CONFIRMED）
源系统：Rescue Mode，...
源盘组合身份：...
固定 SSH 主机指纹：...
目标 SSD：设备=...，型号=...，容量=... bytes
目标序列号：...
数据来源：固定 SSH 主机指纹的 Rescue Mode 整盘流（远端 zstd，SSH 加密传输，本地解压写入）
网络：本次启动已验证 Rescue SSH；不依赖旧 Ubuntu 内部的 VLESS/Tailscale 服务。
数据损失：目标 SSD 的整盘内容将被源盘覆盖，目标盘原有分区和数据会全部丢失。
恢复：离线修复前会在 PAWDATA 保留配置备份；但不等于可恢复目标盘原有数据。
如确认覆盖，请输入目标 SSD 序列号最后 6 位：
```

确认后：`输入已确认；开始整盘覆盖迁移，请不要断电。`

**如果不对**

- 输错 6 位：会显示"确认值与目标 SSD 序列号不匹配，已安全停止，没有写入任何数据。"
  这是正常保护，重新按 `6` 即可。
- 克隆中断：程序会按 `CLONE-INCOMPLETE` 停下，不会假装成功；
  **不要手动继续**，先看报告再决定。
- 独立 SHA256 不一致：绝对不要启动新系统，回到菜单 7 看报告。
- 目标盘容量小于源盘：授权前就会拒绝；换更大的盘。
